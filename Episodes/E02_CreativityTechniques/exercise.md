# Your Content Website

## Overview

During the next weeks we will develop a content website. A content website is a site which mainly delivers content and does not offer extensive interaction possibilities. To do a step forward from pure static html, css and JavaScript we will enable content provisioning via Markdown files.

Since this will keep us busy during the next weeks we will do this by a series of assignments. Every student will have to deliver this site by themself, i.e., every student will choose their unique topic about which the content website has to be developed.

Before starting this assignment, take part in the classroom topic-selection session. Use the topic agreed and recorded for you in class.

This first assignment records your agreed website topic and sets up its repository for the following weeks:

1. **Name your website.** Give your website a name based on your agreed topic.
2. **Create a new repository on GitHub.** Use the name of your website as a basis for the repository name. Remember the naming conventions discussed in episode 1.
3. **Clone the repository to your computer.** Work in this local repository for the remaining steps.
4. **Describe your planned website in `README.md`.** Create or update this file at the top level of your local repository. Write a short text of about five lines explaining:
   - the topic of your website;
   - its intended audience;
   - two or three examples of content you plan to include.
5. **Commit and push your README.** Use the Git workflow from Episode 1: inspect your changes with `git status`, stage `README.md` with `git add`, create a commit with a meaningful message using `git commit`, and send it to GitHub with `git push`. Open your repository on GitHub and check that your README contains the committed text.

**Result:** Your topic is agreed and recorded in class. You have a GitHub repository named after your website, a local clone, and a committed and pushed `README.md` describing the topic, audience, and planned content.
