# Act I — Unit 1: Version Control — The Basic Commands

## Where do we start?

We are starting a new project. GitHub will be the central place where we store and keep track of our project.

## What is the problem?

We want to work on our project locally without losing track of our changes.

At the same time, our project should be available on GitHub so that we can access it from anywhere and later use GitHub for collaboration, automation and deployment.

## How do we want to solve it?

We use **Git** for version control and **GitHub** to host our repository.

Our basic workflow is:

```text
GitHub
   ↓ clone
Local Repository
   ↓ change
Working Files
   ↓ add
Staged Changes
   ↓ commit
Local Repository
   ↓ push
GitHub
```

We will use this workflow throughout the course.

## Where are we now?

We have our own repository on GitHub and a local copy on our computer.

We can make changes, create commits and synchronize our local repository with GitHub.

## What can I practice?

- Create and clone a GitHub repository.
- Make several small changes and commit them separately.
- Use `git status` frequently and try to understand its output.
- Use `git diff` to inspect your changes.
- Push your commits and verify them on GitHub.
- Make a small change on GitHub and retrieve it with `git pull`.
- Inspect your project's history with `git log`.
